# Архитектура библиотеки HorecaBot

## Введение

HorecaBot построен на модульной архитектуре, которая позволяет легко расширять функционал и адаптировать библиотеку под конкретные нужды заведения. В основе лежит базовый класс `HorecaBot`, от которого наследуются специализированные классы для разных типов заведений.

## Базовый класс HorecaBot

### Основные компоненты

```python
class HorecaBot:
    def __init__(self, token, name, timezone, currency, establishment_type):
        # Основные атрибуты
        self.token = token                    # Токен Telegram бота
        self.name = name                      # Название заведения
        self.timezone = timezone              # Часовой пояс
        self.currency = currency              # Символ валюты
        self.establishment_type = establishment_type
        
        # API
        self.api_url = f"https://api.telegram.org/bot{token}"
        
        # Обработчики
        self.handlers = {}                    # Обработчики команд
        self.message_handlers = []            # Обработчики сообщений
        self.callback_handlers = {}           # Обработчики callback
        
        # Модули (инициализируются в дочерних классах)
        self.menu_module = None
        self.booking_module = None
        self.quiz_module = None
        self.loyalty_module = None
```

### Основные методы

#### Работа с Telegram API

- `send_message(chat_id, text, reply_markup)` — отправка сообщения
- `send_photo(chat_id, photo, caption)` — отправка фото
- `edit_message_text(chat_id, message_id, text)` — редактирование сообщения
- `answer_callback_query(callback_query_id, text)` — ответ на callback

#### Регистрация обработчиков

- `@command(command_name)` — декоратор для команд
- `@on_message` — декоратор для текстовых сообщений
- `@on_callback(callback_data)` — декоратор для callback-кнопок

#### Создание клавиатур

- `create_inline_keyboard(buttons)` — inline-клавиатура
- `create_reply_keyboard(buttons)` — reply-клавиатура

#### Управление ботом

- `start_polling()` — запуск long polling
- `run()` — упрощенный запуск бота
- `stop()` — остановка бота

## Веб-панель аналитики

### Архитектура

Веб-панель построена на Flask и предоставляет:

1. **Авторизация** — защита доступа логином/паролем
2. **Dashboard** — ключевые метрики
3. **API endpoints** — REST API для получения данных
4. **Экспорт данных** — CSV/Excel

### Основные страницы

- `/` — главная панель с метриками
- `/guests` — список гостей
- `/menu` — управление меню
- `/bookings` — бронирования

### API

- `GET /api/guests` — список всех гостей
- `GET /api/guests/<user_id>` — детали гостя
- `GET /api/menu/popular` — популярные позиции
- `GET /api/bookings/today` — бронирования на сегодня

## Асинхронность

Библиотека использует:
- `asyncio` — для асинхронного выполнения
- `aiohttp` — для HTTP-запросов к Telegram API

**Long Polling:**
```python
async def start_polling(self):
    while self.running:
        updates = await self.get_updates(offset=self.last_update_id + 1)
        for update in updates:
            await self.process_update(update)
```

## Расширяемость

### Добавление нового модуля

1. Создать класс модуля в `horecabot/modules/`
2. Добавить экспорт в `horecabot/modules/__init__.py`
3. Инициализировать в специализированном классе

### Добавление нового типа заведения

1. Создать класс, наследующий `HorecaBot`
2. Реализовать `_setup_default_handlers()`
3. Добавить специфичные методы
4. Экспортировать в `horecabot/__init__.py`

## Безопасность

- **Токен бота** — хранить в переменных окружения
- **Веб-панель** — защищена авторизацией
- **Валидация входных данных** — на уровне модулей
- **SQL-инъекции** — защита через ORM (SQLAlchemy)

## Производительность

### Оптимизации

1. **Кэширование** — меню и часто используемые данные в Redis
2. **Пакетные операции** — группировка запросов к БД
3. **Асинхронность** — параллельная обработка обновлений
4. **Индексы БД** — на часто запрашиваемых полях

### Масштабирование

- **Горизонтальное** — запуск нескольких экземпляров бота
- **Вертикальное** — увеличение ресурсов сервера
- **База данных** — переход с SQLite на PostgreSQL
- **Кэш** — использование Redis для session storage
